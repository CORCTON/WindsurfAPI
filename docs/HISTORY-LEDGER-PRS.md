### #226 —— pair-chain 稳定 session_id（warelik，S）

- **架构**：`src/session-continuity.js` 600 行、零 npm 依赖。从对话自身的 request/response pair 链推导稳定 session_id——身份只来自客户端可见的输入/输出，显式不用 requestId/IP/时间戳（这三者要么客户端可见可伪造、要么不稳定）。
- **稳定机制**：root anchor 让 id 从第 1 轮就稳定（首轮输入即锚点）；provisional-claim 规则让「同开场白」的对话第 2 轮分叉（第二轮输入不同 → 各自 claim）；TTL 30min + LRU 500 双重有界，防内存无限增长。
- **实测**：真实上游（glm-5.2）两段各 3 轮对话均 3 轮同 id。
- **修复对象**：每轮新 session_id 在上游 velocity limiter 眼里放大账号级限流压力。
- **评级姿态**：对「能否降低 429 频率」这种无法短 smoke 证明的问题保持正确保守——先证伪「重复 session_id 会不会被上游拒绝」这个关键风险，再谈收益。
- **后续**：无 fix 类；`e980bc2` docs 注释指回，`9bbab01`/`a9e8a49` 为 #242 的 commit。

### #61 —— Opus 4.7 五件事（baily-zhang，S+）
