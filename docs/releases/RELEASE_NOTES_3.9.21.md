## Bash 前缀修复:五个洞,逐个实测(第 7 条)

`startsWith` 单独使用允许**词中扩展**,所以上面那两个例子里网关不是在延长命令,
是在**推翻**它。五处已封,每处都有实测:

- **词边界** —— 只在 token 边界上匹配
- **不引入新命令** —— `COMMAND_CHAINING_RE`
- **否定掩码** —— 复用 NLU 层的实现,不再写第二份
- **来源可信度** —— 原先取的是任意尾部 user 消息,于是一个 `<tool_result>` 载荷
  能让**工具输出**成为命令来源
- **猜测的边界** —— 无反引号的模式会一路捕获到行尾,于是
  "run rm -rf varlog happened in the report" 整段成了 argv,里面没有元字符可供
  链式检查发现

## 文档来源:封完上面四处之后才发现的第五扇门

Anthropic 在**块级别**区分附件和调用方自己的话。而这一层把两者拼进了同一条
消息,拼完之后下游再也分不开。实测:一份写着
``run `npm install --force --unsafe-perm` `` 的文档,能让修复逻辑把这些 flag
叠加到模型原本的 `npm install` 上。

现在解码出的文档文本在翻译阶段就打标,在修复阶段被清空。**清空而不是跳过整条
消息是承重的** —— 附件和指令共享同一条消息。

## 其余修复

| 面 | 缺陷 | 修法 |
|---|---|---|
| Responses store(第 9、10 条) | 报告指的分支实际**不可达**:`commit` 在 `!chainable` 时就返回,所以 `putResponse` 的 `!callerKey` 那行永远不会从唯一调用点触发,而那行是唯一会累加 `_stats.rejected` 的地方 | 两处都作为**潜伏守卫**修,测试也这么写,不假装是活缺陷。另外读取不再越过最后一条 user 轮次（实测:最后问的是 "And 3+3?",GET 却返回 "It is 4."）,拒绝存储会打日志而不是一个来回之后变成 404 |

## 租户隔离的前提被钉住了

README 的 `RESPONSE_STORE_ENABLED` 条目早就写明:租户隔离靠的是 response id 的
**90 bit 熵**(`resp_` + UUIDv4 去横线取前 24 个 hex),**不是**客户端自称的 scope ——
共享一个 API key 时 callerKey 里的 `user` 常是邮箱或账号 id,可猜。但那段话当时
没有任何测试。

先验证了它纠正的那个前提:**共享同一个 API key 时,两个调用方发送相同的 `user`
会推导出逐字节相同的 callerKey**。四条断言现在钉住了 id 的宽度和随机性 ——
收窄它不会再静默地让文档变成假话。
