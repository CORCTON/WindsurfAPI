# v3.9.33

工具前言阶梯**不再构造注定被丢弃的那一档**：病态 schema（`$ref` 钻石）从 11.4 ms 降到 0.91 ms（**−92%**），
普通请求**无可测变化**。无 API 破坏：响应逐字节相同。ACU `^22` 仍默认关。`FREE_TIER_SELECTOR` 仍是 `swe-1-6-slow`。

## 用户可感知

### 病态工具 schema 的构造时间降 92%，普通请求不受影响

工具前言有个四档阶梯（full → schema-compact → skinny → names-only），逐档降到塞进 `TOOL_PREAMBLE_SOFT_BYTES`（默认 24 KB）为止。
问题在 **schema-compact** 那一档：它会把 schema 里每个 `$ref` 内联展开，**而一个 `$ref` 在兄弟位置重复出现会乘法式爆炸**。
于是一条带钻石形 `$ref` 的工具参数，会先被展开成 **约 1.09 MB** 的字符串，再被阶梯**原样丢弃** —— 因为它远超上限。
**代价付了，产物从来没被用过**，而且那几毫秒阻塞的是所有租户共享的那一个线程。

本版让这段内联在**已经证明超过上限**时就停下，并**把"这一档被丢弃"作为信号报告给阶梯**（而不是返回一个被剪短的前缀）。
实测（无 hook 协议，6 轮 × 40 次迭代，交替顺序，sha256 校验换文件）：

| 形状 | 阶梯耗时 | 请求耗时 |
|---|---|---|
| `$ref` 钻石 14 层 | 10.741 → **0.455 ms（−95.8%）** | 11.357 → **0.911 ms（−92.0%）** |
| `$ref` 钻石 12 层 | 4.908 → **0.507 ms（−89.7%）** | 5.025 → **0.907 ms（−82.0%）** |
| 34 个普通工具 | 1.604 → **1.493 ms（−7.0%）** | 3.411 → 3.331 ms（−2.3%，**在噪声内**） |

**普通路径不做提速声明。** 请求级个位数百分比在这台机器上不可分辨：2×2 析因（臂位 × 文件）给出臂位偏置 **+3.6%**，
而文件效应 **−0.6% 且两个臂内符号相反（−1.5% / +2.8%）**。**阶梯那一档是稳的（−9.3%，两个方向同号）**，
请求那一档不是 —— 所以本版只声明阶梯。

**响应逐字节相同**，由三条独立的钉住：① 每个形状、每一轮、每次迭代的响应 sha256 都是同一个值；
② 96 条 golden **一条没动**，另从干净 `ref-master` 树在 golden 未覆盖的上下限组合上抓了 48 条，**0 条不同**；
③ 一条新测试把真实阶梯与"每一档都不设上限"的参照阶梯在全部 96 个设置上对拍（tier / ok / compacted / fullBytes / finalBytes / sha256）。

**那条诊断没有丢，反而覆盖更广**：`$ref` 内联撞预算的警告在钻石形上仍然触发，而且**对直接（无上限）调用方，节点预算那一支的文案与 v3.9.32 逐字节相同**（`assert.deepEqual` 钉住）。

## 工程

### PR 模板不再教贡献者用一个会截断测试运行的 flag

`--test-force-exit` 已从 `package.json`、`scripts/run-test-shard.mjs` 与三个 harness 脚本移除；
本版补上最后一处漏网：`.github/PULL_REQUEST_TEMPLATE.md` —— **那是外部作者动手前唯一会读的地方**，
也是 #266 作者照抄那条命令的原因。它在 Linux runner 上会**跑完一部分 suite 就让进程退出，而且仍然 exit 0**：
同一份字节跑 12 次得到 **8 个不同计数（34…72）**，去掉后 **10/10 稳定**。

### 量具的一个发现（比这次改动更有价值，已写进 harness 注释）

带 hook 的 A/B 量具**在没有任何处理效应时**就会造出 2–3% 的差异；同一份代码放在镜像的臂位上会从 **+11.5% 变成 −0.7%**；
还出现过一轮 **+70%** 的离群。所以**任何低于 ~10% 的请求级比较，都必须用无 hook 协议**。
另一条已记录：A/B 驱动会在磁盘上**交换**被测文件，所以 `git status` 可能在某几百毫秒内把那个文件报成"未修改"——
**要从 git 里读产物，不要从正在被编辑的工作树里读。**
